# 在讲解处渲染 Remotion 动画

## 先决定画什么

用一句话填空：“用户看完，应能指出 ___ 怎样从 A 变到 B，以及原因。”填不出明确变化，改用文字或静态图。根据机制选择画面，而不是给标题和要点添加转场：

| 难点 | 让什么动 | 保持什么不动 |
| --- | --- | --- |
| 区间、算法、队列 | 指针、候选边界、对象位置 | 数值、身份标签和参照位置 |
| 数据/消息流 | 一条具体记录经过各步骤时的内容与去向 | 节点顺序、同一记录的标识 |
| 函数和参数变化 | 固定其他条件，只改一个参数，更新点或曲线 | 坐标尺度、单位和基准线 |
| 同步比较两种方法 | 对相同输入同时推进一个步骤 | 观察指标和时间起点 |

从当前课选择一个小例子，先核对每个中间状态。用 2–4 个节拍表达“起点 → 关键变化及原因 → 结果”；只展示当前步骤。使用与正文相同的变量、数值、语言和颜色含义。理想化轨迹、慢放或非等比示意应明确标注。非连续状态不要为了平滑而制造不存在的中间值。

## 本地执行

1. 优先复用当前项目中已授权、可运行的 Remotion 环境。否则将本技能的 `assets/remotion-lesson/` 整个复制到本次学习工作区的独立可写目录，在副本内执行下列命令。不要改写安装好的 Skill、已有课程或其他项目的依赖。为每个讲解选择独立输出目录；已验证的同一内容可以复用。
2. 按概念在副本中改写 `lesson.jsx` 的图形、状态和转移，保留 `Lesson`、`fps`、`durationInFrames` 三个导出。`index.jsx` 注册 1280×720 的 `Lesson`。内置示例是“在升序数组找 16”：比较 12 → 23 → 16；不是所有课程通用的换字模板。原示例之外，不得不改示意图就渲染交付。
3. 检查本地 Node.js、npm、浏览器、依赖和宿主执行权限。依赖已就绪时直接渲染；缺少依赖时，仅在允许联网及安装的环境中运行 `npm install --no-audit --no-fund`（有锁文件时使用 `npm ci --no-audit --no-fund`）。首次渲染可能下载浏览器；禁止联网时不要尝试下载。不得为了动画全局安装、擅自上传课件或修改系统配置。
4. 从该副本运行 `npm run render`，产物为 `out/lesson.mp4`（H.264，无声）。已安装兼容 Chrome/Chromium 时，可用 `npm run render -- --browser-executable="实际的浏览器绝对路径"`，将路径替换为已确认的可执行文件。仅生成源码、打开 Studio 或成功列出合成不算渲染完成。
5. 检查渲染退出码、文件非空、视频流/时长，抽看起点、关键变化和末尾的画面。需要独立核对布局时使用 `npm run still -- --frame=帧号`，选择实际时长内的帧；此命令每次覆盖副本中的 `out/check.png`。核对状态顺序、中文缺字、字号、字幕停留和遮挡；不能仅凭文件存在宣布画面正确。

## 放回讲解，而非另起一篇视频报告

- 视频前只给观看线索（例：“看下方括线：每次比较后，哪一段还可能包含 16？”）。在该段展示本地 MP4，宿主不支持内嵌则给可访问的附件或文件链接；不要给不能访问的临时路径。视频后用一句话说明观察到的规律，接回原模式的练习或复述。
- 保证不播放也能懂：正文保留关键状态、前提和结论；不要强制自动播放、循环、配音或依靠颜色区分状态。用标签、形状或位置提供第二种线索，避免闪烁。
- 环境不支持、依赖不可用、渲染失败或无法验收时，不阻塞课程。改用 2–4 个带标签的静态状态或文字步骤，说清未交付动画的原因；不把动画脚本、分镜、静态图或其他视频称作已渲染的 Remotion 成片。

## 路由自检

- “为什么二分查找每次能扔掉一半？”→ 看区间收缩，先标明有序前提，再渲染；不要用字幕轮播代替区间变化。
- “只用文字讲二分查找”／“给我五天学习计划”→ 不运行渲染，不产生视频。
- “考我下一步查哪个数，别告诉我答案”→ 停在题目；作答后如需纠错，只演示已答步骤，不预告下一题。
- 无执行权限时讲同一概念 → 用原数组列三次比较与保留范围；明确这是文字替代，不要求用户先安装软件才能继续学习。
